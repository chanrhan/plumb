# View: 기술 변경 로그 (`/views?view=changelog`)

이슈 #4의 산출물. `README.md`의 공통 레이아웃(상단 바 · 블록 트리)과 출처 표기 규칙 2.1, 코드 열람 점프 2.2를 전제로 한다. 이 View는 기획안 §6.2 "무엇이 바뀌었는지는 도구가 diff에서 감지하고, 이유는 에이전트가 쓴다"를 화면으로 옮긴 것이다.

## 1. 답하는 질문

**무엇이 왜 바뀌었나.** 두 축으로 답한다.

| 축 | 내용 | 출처: 누가 만드나 |
|---|---|---|
| 설계 변경 이벤트 | 도구가 diff에서 **자동 감지**하는 6종: 새 의존성 도입/제거 · 새 블록·블록 경계 변경 · 블록 경계를 넘는 새 의존 관계 · 계약 변경 · 규칙 변경·완화 제안 · 새 외부 시스템 연결 | `git:` diff + `파서:` 전후 비교. 에이전트의 자기 보고에 의존하지 않는다 |
| 결정 기록 D-xxxx | 에이전트가 남긴 결정 · 이유 · 기각한 대안 · 감수한 것 · 연결 규칙 | `저장소:` 결정 기록 파일. 3등급(기록)이며 규범도 검사 대상도 아니다 |

이벤트는 감지됐는데 결정 기록이 없거나 이유가 비어 있으면 **"사유 없음"**이다. 사유 없는 이벤트의 비율이 이 View의 지표(기획안 §14)다. 이 View는 "에이전트가 무엇을 했다고 말했나"가 아니라 "도구가 무엇을 봤고, 그에 대한 기록이 있나"를 보여준다.

## 4. 동작

- **감지 시점.** `plumb check`(M5)와 `plumb views`(M8)가 돌 때 감지기가 마지막 기록 커밋부터 HEAD까지의 diff를 본다. 커밋 단위로 전후 파서 결과(lockfile · 블록 그래프 · depcruise 엣지 · OpenAPI · Prisma)를 비교한다. 결과는 보호 저장소 `changelog/events.jsonl`에 덧붙여 쓴다. 에이전트는 `~/.plumb/**`를 못 읽으므로 이 파일을 고치거나 지울 수 없다.
- **결정 기록 읽기.** 감지와 별개로 `decisions/D-*.md`를 모두 읽어 다섯 필드로 나눈다. 필드가 빠진 기록(기각 없음 등)도 그대로 보이고 빠진 줄에 `(비어 있음)`을 적는다. 이유가 비어 있으면 그 기록이 연결된 이벤트는 "사유 없음(empty-reason)"이다.
- **지표 계산.** 기간 필터 안의 이벤트로 비율을 계산해 상단에 둔다. 검사마다 그 시점의 비율을 검사 결과 이력에 남겨 추이를 그린다.
- **펼침.** 이벤트 행을 누르면 감지 근거 표와 결정 기록 전문이 펼쳐진다. 결정 기록은 항상 "저장소: 3등급(기록)" 머리글을 단다. 같은 결정 기록이 여러 이벤트(E-0012·E-0013)에 연결될 수 있고, 그때 각 이벤트에서 같은 전문을 보여준다.
- **점프.** 근거의 `file:line`을 누르면 이유 종류(View 오류 · 정보 부족 · 디버깅·환경)를 고른 뒤 IDE가 열린다. 결정 기록 본문에는 점프 링크를 만들지 않는다 (에이전트가 쓴 경로는 검증되지 않았다).
- **블록 트리 연동.** 좌측 블록 트리에서 블록을 누르면 블록 필터가 그 블록으로 바뀐다. "미분류"를 누르면 블록이 미분류인 이벤트만 남는다.
- **정렬.** 기본은 최신 커밋 우선. 커밋 안에서는 이벤트 ID 순.
- **사유 없음만.** 켜면 지표의 분자에 해당하는 행만 남는다. 지표 숫자는 필터와 무관하게 기간 안 전체를 기준으로 유지한다.
- **이 View가 하지 않는 것.** 결정 기록을 화면에서 쓰거나 고치지 않는다. 결정 기록은 에이전트가 세션 안에서 남기는 것이고, 개발자가 사유를 대신 써 넣으면 지표가 의미를 잃는다. "사유 없음"을 검토 대기열로 보내는 것은 M10 작업 화면 범위다.

## 5. 비어 있을 때

목 데이터로 채우지 않는다. 각 상태는 실제 파일 유무로 정해진다.

| 상태 | 판정 | 화면 |
|---|---|---|
| 감지기가 한 번도 안 돌았다 | `changelog/events.jsonl` 없음 | "아직 감지하지 않음. `plumb views changelog` 또는 `plumb check`를 실행하면 마지막 검사 커밋부터 HEAD까지를 본다." 지표 자리는 비운다 |
| 돌았지만 이벤트 0개 | 파일 있음, 기간 안 행 0 | "기준 `a1b2c3` 이후 설계 변경 이벤트 없음 (n 커밋 검사)". 지표는 "이벤트 없음" |

| 결정 기록은 있는데 이벤트가 없다 | `decisions/` 있음, 이벤트 0 | 목록 아래에 "이벤트에 연결되지 않은 결정 기록 n개" 접힌 절. 전문은 펼치면 보인다. 에이전트가 설계 변경 없이 기록만 남긴 경우이며 지표에 들어가지 않는다 |
| 필터 결과 0개 | 필터 적용 후 0 | "조건에 맞는 이벤트 없음". 지표는 유지 |

## 6. 열린 질문

#5 타입 설계로 넘길 것:

1. `ChangeEvent` 타입: `id`, `kind`(6종 enum), `blocks[]`, `commit`, `session?`, `at`, `evidence[]`(`{ source: '파서'|'git'|'실행'|'저장소', file?, line?, before?, after? }`), `decisionIds[]`, `noReason: null | 'no-record' | 'empty-reason'`. 이벤트 ID의 멱등 키(근거 해시)를 타입에 둘지.
2. `DecisionRecord` 타입: 다섯 필드 + `links: { rules[], events[], commits[] }`. "연결"에 이벤트 ID를 쓰게 할지, 커밋 해시만 쓰게 할지. 이벤트 ID는 감지 뒤에만 존재하므로 에이전트가 기록을 쓸 때는 알 수 없다 → 커밋 해시 + 블록으로 매핑하고 이벤트 ID는 도구가 역으로 채우는 쪽이 자연스럽다.
3. 결정 기록 필수 네 항목 중 `이유` 외의 것(기각 · 감수)이 비면 "사유 없음"인가, 별도 "기록 불완전"인가. 지표 정의(§14)는 "사유 없는" 이므로 이유만 보되, 불완전 수를 따로 세는 안을 제안한다.
4. 검사 결과 이력(`CheckResult`)에 이 View의 비율 값을 넣을지, 별도 `metrics.jsonl`로 뺄지.
