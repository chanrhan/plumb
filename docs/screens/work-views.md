# View 보기 화면 (`/views`)

이슈 #2의 산출물. `docs/screens/README.md`(화면 목록 1, 공통 레이아웃 2, 출처 접두어 2.1, 코드 열람 점프 2.2, API 3.3)를 전제로 한다. View 6개 각각의 내용은 #3·#4가 그리므로 여기서는 **틀**(탭 · 필터 · 본문 영역 · 점프 링크 · 생성 정보)만 그린다.

## 1. 목적

**코드 대신 무엇을 읽는가.** 개발자가 코드를 열지 않고 시스템을 이해하기 위해 매일 여는 화면이다. 코드가 필요해지면 이 화면이 IDE로 보내고, 그 사실을 기록한다.

## 4. 동작

**탭 전환.** 탭 클릭 → URL `?view=<name>` 갱신 (히스토리에 남긴다) → `GET /api/views/<name>` → 본문 교체. 블록 필터(`?block=`)는 탭을 바꿔도 유지된다.

**블록 필터.** 블록 트리 클릭 → `?block=<name>` → 본문에서 그 블록 태그가 붙은 항목만 남긴다. 서버 요청은 없다 (본문은 이미 전부 받았고, 필터는 클라이언트에서 한다). 필터 결과가 0개면 "payment 에 해당하는 항목 없음".

**코드 열람 점프.** `[IDE ↗]` → 대화창 → 이유 선택 → `[IDE에서 열기]` → `POST /api/open { view, item, file, line, reason, note }` → UI 서버가 `store.codeOpens.append()` 후 `ide.open()` (README 2.2). 응답 200이면 대화창이 닫힌다. 열람 횟수가 1 오른다.

**오류 상태.**

| 상황 | 화면 |
|---|---|
| `GET /api/views/:name` 401 | 본문 대신 "세션이 없습니다. `plumb ui` 를 다시 시작하면 브라우저가 `/auth` 로 열립니다" (README 3.2. 토큰 재발급은 서버 재시작뿐) |
| `GET /api/views/:name` 404 | 5절 "비어 있을 때" |
| Mermaid 렌더 실패 | 그 블록 자리에 원문 코드 블록을 그대로 보이고 위에 "다이어그램 렌더 실패" 한 줄. 본문의 나머지는 정상 |
| `POST /api/open` 이 IDE 명령 실패를 돌려줌 (설정 `ide` 명령이 없거나 종료 코드 ≠ 0) | 대화창에 "IDE를 열지 못함: <명령>" 표시. 기록은 결과 `failed` 로 남긴다 (열린 질문 3) |
| 생성 커밋 ≠ HEAD | 하단에 `⚠ HEAD와 다름`. View는 그대로 보인다 (오래된 View를 숨기지 않는다) |
| UI 서버 꺼짐 | 브라우저 수준 오류. 이 화면이 할 일 없음 |

## 5. 비어 있을 때

목 데이터는 쓰지 않는다 (CLAUDE.md "하지 않는 것"). 데이터가 없으면 없다고 보인다.

| 없는 것 | 화면 |
|---|---|
| `views/` 디렉토리 자체가 없음 (한 번도 `plumb views` 를 안 돌림) | 탭 6개 전부 비활성. 본문: "아직 생성된 View 없음. `plumb views` 를 실행하면 파서 출력에서 만들어집니다". 생성 출처 표시줄과 하단 생성 정보는 `—` |
| 선택한 View 파일만 없음 (예: 흐름도는 OTel spike 전) | 그 탭만 비활성. 눌렀을 때 "`flow` View 아직 없음" |
| 블록 그래프 없음 (M1 #9 빈 뼈대 상태) | 블록 트리: "블록 아직 없음". 필터 칩 없음. 본문은 필터 없이 전부 보인다 |
| `code-opens.jsonl` 없음 | 열람 횟수 `열람 0회` |
| 본문이 있으나 `file:line` 이 하나도 없음 | 링크 없이 본문만. 별도 표시 없음 |
| 머리말에 `commit` 없음 | 하단 "생성 커밋 기록 없음". 오래됨 비교는 하지 않는다 |

## 6. 열린 질문

1. **항목별 블록 태그와 `file:line` 의 표현 형식** (→ #5). Markdown 본문에 항목 단위 메타데이터를 어떻게 싣는가. 후보: (a) HTML 주석 `<!-- plumb: block=payment file=... line=42 -->`, (b) View 파일을 Markdown이 아니라 JSON 구조로 두고 렌더러가 Markdown을 만든다. (b)면 `GET /api/views/:name` 의 응답 타입이 바뀐다.
2. **`views/<name>.md` 머리말 타입** (→ #5). `generatedAt`, `commit`, `sources[]` 의 필드. `sources[]` 항목이 README 2.1 접두어를 그대로 쓰는지.
3. **IDE 열기 실패 시 기록.** 실패도 `code-opens.jsonl` 에 남길지(명제 검증에는 "보려 했다"가 중요), 남기면 `result` 필드가 필요하다 (→ #5 `CodeOpenRecord`).
4. **블록 필터의 L0 선택.** 시스템(L0)을 고르면 필터 해제와 같은가, 아니면 L1 미분류를 제외하는가. M8에서 정한다.
5. **README 보완 후보.** 3.3 API 표에 `GET /api/views/:name` 의 404 (View 없음) 와 머리말 반환 방식이 없다. #5에서 응답 타입을 정할 때 같이 적는다.
