# test/acceptance — 인수 테스트

**테스트 작성 에이전트만 쓴다. 구현 에이전트는 이 디렉토리를 수정할 수 없다**(기획안 §8.1).

- 규칙 상태의 근거는 **여기 있는 테스트뿐**이다(§8.2). `src/**/*.test.ts`의 단위 테스트는 구현자 영역이며 규칙의 근거가 아니다
- 파일 이름은 `*.spec.ts`. `vitest.config.ts`의 `include`가 `test/**/*.spec.ts`를 잡는다
- 테스트는 항상 실패로 시작한다(§8.3). 규칙이 승인된 뒤 테스트 작성자가 여기에 쓰고, 구현자가 `src/`를 고쳐 통과시킨다
- 결과는 `reports/junit.xml`(JUnit XML)로 나온다. M5 `plumb check`가 이 파일을 읽는다(§4.2)
- 격리(§8.1·M4): 테스트 작성자는 `src/**`를 읽지 못하고, 구현자는 `test/acceptance/**`에 쓰지 못한다. 하네스가 강제한다

지금은 비어 있다. 첫 규칙 `pay.refund-window`(§5.2)의 인수 테스트가 첫 파일이 된다.
